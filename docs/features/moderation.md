# Блокировки и жалобы

Источник схемы — `0022_email_verification_and_ugc_safety.sql`; маршруты — `backend/cmd/api/main.go`; реализация — `handlers/moderation.go`, `repository/blocks.go`, `repository/reports.go`.

## Блокировки

| Метод | Путь | Действие |
|---|---|---|
| POST | `/users/:id/block` | Заблокировать пользователя |
| DELETE | `/users/:id/block` | Снять собственную блокировку |
| GET | `/users/blocked` | Список собственных блокировок |

Все маршруты требуют Auth; мутации — CSRF. Нельзя блокировать себя. `user_blocks` содержит направленную пару `(blocker_id, blocked_id)`; проверка `IsBlockedBetween` учитывает оба направления.

`Blocks.Block` в одной транзакции создаёт блокировку, удаляет дружбу/заявку, взаимные дефолты и исключения видимости, взаимные уведомления. Хендлер инвалидирует кеш обоих пользователей. Поиск пользователей исключает блокировки в обоих направлениях; новая заявка также проверяет блокировку. Снятие блокировки удаляет только собственную строку: дружба и настройки не восстанавливаются.

Блокировка не является общим middleware для всех маршрутов. При добавлении новых способов взаимодействия проверяйте доступ в конкретном репозитории; не считайте наличие строки в `user_blocks` автоматическим фильтром каждого API-ответа.

## Жалобы и администрирование

`POST /reports` принимает `reported_user_id`, `entity_type` (`entry`, `comment`, `user`), опциональный `entity_id`, обязательную непустую `reason` и `details`. Хендлер проверяет UUID пользователя и тип сущности; некорректный опциональный `entity_id` превращает в `nil`. Это не полная проверка принадлежности и доступности указанной сущности.

Жалобы хранятся в `content_reports`, статусы — `pending`, `reviewed`, `dismissed`.

| Метод | Путь | Действие |
|---|---|---|
| GET | `/admin/reports` | Список, фильтр `status`, `limit` до 100, `offset` |
| PATCH | `/admin/reports/:id` | Изменить статус |
| POST | `/admin/reports/:id/delete-content` | Удалить запись или комментарий по жалобе |

Админ-маршруты требуют Auth и Admin; мутации — CSRF. Удаление записи использует `Entries.DeleteAdmin`, затем пытается удалить вложения из S3. Для комментария вызывается `Reports.DeleteCommentAdmin`. Обработка `entity_type=user` не удаляет аккаунт; не используйте этот маршрут как API удаления пользователей.

Фронтенд: `ReportModal.jsx`, `BlockedUsersModal.jsx`, `AdminReports.jsx`, `src/api/users.js`, связанные хуки в `queries.js`. Проверки входных данных — `handlers/moderation_test.go`; полноценные интеграционные гарантии требуют отдельной БД.
