# Поиск по своему дневнику

Экран `/entries/search` открывается из собственного календаря. Лупа расположена внутри блока «Мой календарь» рядом со стрелкой раскрытия и отсутствует в чужом календаре. Фильтры раскрываются кнопкой рядом с поисковой строкой. Результаты оформлены карточками без свечения. Запрос и фильтры сохраняются в URL при переходе к записи и возврате назад.

- `GET /entries/search` доступен только после авторизации и всегда ограничен `userID` из middleware. Включает скрытые записи владельца. Ответ помечен `Cache-Control: private, no-store`.
- `q`: буквальное вхождение слова или фразы в `entries.text`, без учёта регистра, с заменой «ё» на «е». Символы `%`, `_` и `\` экранируются для LIKE. Максимум 200 символов.
- `from`, `to`: включительные границы дат. Месяц преобразуется клиентом в его первый и последний дни.
- Повторяемый `mood`: любое из выбранных настроений 1–5. Повторяемый `tag`: запись содержит все выбранные теги (точные значения, максимум 30).
- `photo=true`, `audio=true`: обязательное наличие соответствующего вложения. Расшифровка аудио не выполняется.
- Результаты отсортированы по дате от новых к старым. Порция — 20 записей, `next_cursor` — дата последней выданной записи. Уникальность `(user_id, date)` обеспечивает keyset-пагинацию без OFFSET.
- `GET /entries/tags` возвращает уникальные теги только своих записей; клиент объединяет их со стандартными тегами.

Поиск использует существующий индекс по владельцу/дате и проверяет текст только среди записей владельца. Миграций нет. Отдельное поле личной заметки в эту функцию не входит.

Проверки: `node --test src/utils/entrySearch.test.js` во frontend; `go test ./...` в backend. Для проверки SQL, изоляции владельца, скрытых записей, фильтров и пагинации задайте `SEARCH_TEST_DATABASE_URL` для локальной БД с актуальной схемой и выполните `go test ./internal/repository -run TestEntrySearchDatabase -count=1`. Тест создаёт собственные аккаунты и удаляет их после завершения.
