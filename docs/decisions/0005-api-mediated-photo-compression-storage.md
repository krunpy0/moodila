# ADR-005: Загрузка медиафайлов через API с серверным сжатием изображений

Status: Accepted

## Context
Современные мобильные устройства создают фотографии высокого разрешения (12–48 Мп) с размером файла от 3 до 15 МБ. При классической схеме прямой загрузки браузера в объектное хранилище (S3 Presigned PUT URL) возникают серьезные проблемы:
1. **Трафик и скорость загрузки ленты:** Хранилище заполняется многомегабайтными оригиналами. У друзей пользователя при прокрутке ленты на мобильном интернете фотографии открываются с многосекундными задержками.
2. **CORS провайдера:** Прямая загрузка из браузера в S3 требует сложной настройки CORS-заголовков (`Access-Control-Allow-Origin`, `PUT`) на стороне каждого провайдера хранилища (AWS S3, Cloudflare R2, MinIO, Backblaze B2).
3. **Безопасность:** Отсутствует возможность валидации содержимого файла перед сохранением (риск загрузки вредоносных бинарников под видом картинок).

## Decision
1. Реализовать двухшаговый защищенный флоу загрузки:
   - **Шаг 1:** Клиент запрашивает подготовку загрузки: `POST /storage/entry-photos/upload-url` с указанием имени файла, `content_type` и размера. Сервер валидирует допустимость расширения, формирует канонический путь `users/{user_id}/{YYYY/MM}/{random_hex}.{ext}` и возвращает JWT-тикет со сроком жизни 10 минут (`uploadClaims`).
   - **Шаг 2:** Клиент отправляет бинарный поток файла методом `PUT /storage/entry-photos/upload/:token` непосредственно на Go API.
2. **Серверное сжатие и нормализация (Go API):**
   - Бэкенд считывает поток, декодирует изображение (`image/jpeg`, `image/png`).
   - Ограничивает габариты: если длинная сторона превышает 1920 пикселей, выполняется пропорциональный даунскейл (максимальное разрешение 1920x1920).
   - Пережимает изображение в формат JPEG с коэффициентом качества 80 (`jpeg.Encode(..., &jpeg.Options{Quality: 80})`).
   - Сжатый буфер стримится в S3 через метод `s.Put()` от имени сервера.
3. Аудиозаписи (голосовые заметки) передаются через аналогичный подписанный токен, но сохраняются без дополнительной перекодировки.

## Reason
- **Экономия диска и трафика на 50–80%:** Размер фотографий уменьшается в 3–5 раз без видимой потери качества на экранах смартфонов.
- **Отсутствие проблем с CORS хранилища:** Браузер общается исключительно с API Moodila, для которого CORS уже настроен на уровне Gin middleware.
- **Гарантированная валидация контента:** Файлы, не являющиеся валидными изображениями, отсекаются на этапе декодирования заголовков.

## Consequences
- Сервер кратковременно утилизирует CPU на операциях изменения размера и перекодирования JPEG (лимитируется через Rate Limiter: 10 загрузок / 4 сек).
- Максимальный размер загружаемого исходного файла ограничен 10 МБ (`maxPhotoBytes = 10 * 1024 * 1024`).

## Alternatives
- **Чистый Presigned PUT в S3:** Отвергнуто из-за отсутствия сжатия и проблем с CORS у разных S3-провайдеров.
- **Асинхронное сжатие через AWS Lambda / Worker:** Отвергнуто из-за усложнения инфраструктуры и необходимости поддержки дополнительных облачных сервисов.
