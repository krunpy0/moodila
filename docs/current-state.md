# Текущее состояние проекта

Дата сверки с исходным кодом: **9 ноября 2026 года**. Это описание репозитория, а не подтверждение состояния production или результатов нагрузочного тестирования.

## Реализованные подсистемы

- Дневник: одна запись на дату, настроение 1–5, теги, текст, фото, аудио, глобальная и персональная видимость. `support_preference` позволяет указать ожидаемую поддержку и закрыть новые комментарии.
- Главная страница с быстрым вводом настроения, свой календарь и календари друзей, аналитика, поиск по своему дневнику с фильтрами и keyset-пагинацией.
- Дружба, лента с реакциями и комментариями, блокировки, жалобы и административная обработка жалоб.
- Cookie JWT, обновление сессии, смена/сброс пароля, подтверждение email, удаление аккаунта по email, экспорт через `/users/me/export`.
- Уведомления в приложении, настройки категорий, Web Push с локализацией `ru`/`en`, объявления и онбординг.
- PWA, RU/EN интерфейс, мобильная и desktop-компоновка. Семь постоянных семейств тем (14 вариантов) и два сезонных (ещё 4 варианта).
- Лендинг с интерактивными превью реальных экранов в отдельном `landing-preview.html`; демонстрационные запросы обслуживает локальный transport.

## Известные ограничения

- `middleware.Auth` проверяет access JWT без обращения к БД. `token_version` сверяется при refresh для положительной версии claim; старый access JWT может действовать до истечения, обычно до 15 минут. Logout очищает cookies и пытается увеличить версию; ошибка инвалидации только логируется.
- CSRF middleware стоит на защищённой группе. Публичные auth POST находятся вне неё. Для `/notifications/mark-read` есть исключение при `Sec-Fetch-Site: same-origin`.
- Email verification реализована как статус и баннер. Общего middleware, запрещающего работу неподтверждённым пользователям, нет.
- `SummaryCache` и очередь push находятся в памяти одного процесса. При заполнении очереди push сообщение отбрасывается с записью в лог. Несколько API-процессов требуют согласованной инвалидации кеша.
- API может стартовать без доступной БД; ошибка миграций логируется и также не останавливает запуск. Запуск процесса не означает готовность схемы.
- Семафор ограничивает декодирование/ресайз фото двумя операциями, но тело загрузки читается до захвата семафора. Это не гарантирует отсутствие OOM.
- В `vite.config.js` настроен runtime-кеш `/entries/*`; при изменении приватности и выхода учитывайте также Service Worker.
- Workflow деплоя собирает фронтенд и бэкенд, но не запускает lint и тесты. Конфигурацию VPS и `/opt/moodila/deploy.sh` нужно проверять на сервере.
