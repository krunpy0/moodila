# Current State of the Project

*Дата актуализации: 07 октября 2026 г.*

Этот документ фиксирует фактическое состояние кодовой базы, архитектурных подсистем, инфраструктуры и известных ограничений проекта **Moodila** по состоянию на текущий момент.

---

## 1. Общий статус проекта

Moodila находится в состоянии **Production-Ready MVP / Feature-Complete**. В кодовой базе реализован весь запланированный объем пользовательской, социальной, аналитической и административной функциональности. Система оптимизирована для стабильной работы на серверах с жесткими ограничениями по ресурсам (1 vCPU / 1 GB RAM).

## 3. Статус ключевых подсистем

### 3.1. Аутентификация и сессии (Authentication & Security)
- **Токены:** Двухуровневые JWT (`access_token` на 15 мин, `refresh_token` на 30 дней) хранятся исключительно в браузерных куках `HttpOnly`, `SameSite` (`Strict` / `Lax` / `None`), с флагом `Secure` в production.
- **Инвалидация сессий:** Поле `token_version` в таблице `users`. При смене пароля или выходе версия инкрементируется, что немедленно делает недействительными все выданные ранее токены без необходимости хранить черный список в Redis.
- **CSRF-защита:** Заголовок `X-CSRF-Token` обязателен для всех мутирующих запросов (`POST`, `PUT`, `PATCH`, `DELETE`). Значение сверяется со случайным hex-токеном, зашитым в claims access-токена.
- **Rate Limiting:** Индивидуальные token-bucket лимитеры на уровне Gin middleware для защиты чувствительных эндпоинтов (auth, сброс пароля, загрузка файлов, мутации).

### 3.2. Социальная лента (Feed & Pagination)
- **Алгоритм формирования:** Лента отображает записи друзей со статусом `accepted` (опционально включая свои посты через тумблер `includeSelf`).
- **SQL-оптимизация:** Запрос переписан с использованием `WITH authors AS ... CROSS JOIN LATERAL (...)` с локальным `LIMIT` на автора (до 11 строк) и составным индексом `idx_entries_user_date (user_id, date DESC, created_at DESC, id DESC)`. Задержка снижена с ~1300 мс до ~7.5 мс на базе в 300 000 записей.
- **Пагинация:** Keyset cursor пагинация по кортежу `(date, created_at, id)`. Курсор кодируется в Base64.
- **Реакции и лайки:** Реакции к записям ленты подгружаются пакетом (`WHERE entry_id = ANY(...)`) и агрегируются в памяти Go, исключая проблему N+1 запросов.

### 3.3. Социальный граф и приватность (Friends & Privacy)
- **Двухуровневая модель приватности:**
  1. Глобальное скрытие (`entry.is_hidden`).
  2. Дефолты на уровне пользователя (`user_friend_visibility.hide_by_default`).
  3. Точечные переопределения на уровне конкретного поста (`entry_friend_visibility.is_hidden`).
- **Изоляция истории от новых друзей:** При принятии дружбы (`friends.Respond`) записи обоих пользователей, имеющие кастомную видимость, автоматически помечаются скрытыми для нового друга.
- **Каскадная очистка:** При удалении дружбы (`unfriend`) все строки дефолтов и оверрайдов между бывшими друзьями немедленно удаляются из БД.

### 3.4. Медиафайлы и хранилище (Storage & Media)
- **Фотографии:** Двухшаговый защищенный флоу через API. Фотографии даунскейлятся до 1920px по длинной стороне и пересжимаются в JPEG с качеством 80 на стороне сервера, после чего стримятся в S3.
- **Голосовые заметки:** Загружаются через подписанные токены напрямую в бакет в формате audio.
- **Нормализация путей:** Все ключи объектов в S3 следуют канонической структуре: `users/{user_id}/photos/...`, `users/{user_id}/audio/...`, `users/{user_id}/avatars/...`.

### 3.5. Объявления и онбординг (Announcements & Onboarding)
- **Серверный инвариант:** Эндпоинт `/announcements/active-prompt` возвращает строго не более 1 активного промпта по детерминированному приоритету severity (`critical` > `warning` > `info`).
- **Разделение состояний:** Таблица `announcement_user_state` разделяет `dismissed_at` (пользователь закрыл прерывающий UI) и `read_at` (пользователь прочитал объявление в инбоксе).
- **Онбординг:** Объявления с типом `onboarding` показываются пользователям в течение первых 7 дней с момента регистрации (`u.created_at >= now() - interval '7 days'`).
- **Изоляция архивных объявлений:** Пользователи не видят стандартные объявления, опубликованные до даты их регистрации (`published_at >= u.created_at`).

### 3.6. Уведомления и Web Push
- **VAPID Web Push:** Браузерные пуши по стандарту RFC 8292.
- **Батчинг рассылки:** При создании новой записи дневника друзьям рассылаются уведомления единым батчем с предварительной фильтрацией по правилам приватности и персональным настройкам `notification_settings`.

### 3.7. Темизация и дизайн
- **12 цветовых вариантов:** 6 семейств тем (Classic, Spooky/Halloween, Forest, Ocean, Lavender, Terracotta, Aurora) с поддержкой Light и Dark вариантов.
- **Сезонный движок:** Серверное управление доступностью сезонных тем через эндпоинт `/app/features` с поддержкой перехода через границу календарного года.
- **Тактильный отклик (Haptic Feedback):** Полная поддержка Web Vibration API для Android и полифил на базе коротких звуковых импульсов для iOS устройств.

## 4. Развертывание и CI/CD

- **CI/CD:** GitHub Actions (`.github/workflows/go.yml`) запускается при пуше в ветку `main`.
  - Сборка фронтенда в Node 22 (`npm run build`).
  - Компиляция бэкенда в Go 1.25 (`CGO_ENABLED=0 go build -ldflags="-s -w"`).
  - Упаковка и копирование артефактов по SSH/SCP в `/opt/moodila/incoming/`.
  - Вызов удаленного скрипта `/opt/moodila/deploy.sh`.
- **Контейнеризация:** Имеется `backend/Dockerfile` (Alpine 3.21) и конфигурации `docker-compose.yml` (Postgres) и `docker-compose.loadtest.yml` (изолированный стенд API + Postgres с ограничениями CPU/RAM).

## 6. Известные ограничения и дефекты тестирования

1. **Дефект аргументов в тесте `hidden_test.go:176`:**
   В файле `backend/internal/handlers/hidden_test.go` на строке 176 при вызове `entriesRepo.UpdateVisibility(ctx, userA.ID, entry1.ID, false)` аргументы `entryID` и `userID` переданы в обратном порядке (сигнатура: `UpdateVisibility(ctx, entryID, userID, isHidden)`). Из-за этого запись не обновляется, и последующая проверка на строке 396 (`User D SHOULD see normal public entry 1`) падает при запуске тестов с подключенной реальной БД. Сам production-код работает корректно.
2. **Отсутствие скрипта тестов во Frontend:**
   В `frontend/package.json` определены только скрипты `dev`, `build`, `lint` и `preview`. Тест-раннер (Jest / Vitest) не настроен, хотя в проекте присутствует тестовый файл `src/utils/halloweenSeasonIntegration.test.js`.
3. **In-Memory кеш сводок (`SummaryCache`):**
   Кэш месячных сводок в `internal/repository/entries.go` хранится в памяти одного процесса Go. При возможном горизонтальном масштабировании на несколько реплик потребуется внешняя инвалидация (Redis или Postgres LISTEN/NOTIFY).
